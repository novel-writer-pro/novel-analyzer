# satirical-worldbuilding

## 定位

将「现实社会痛点」系统性地映射为「修仙世界设定」，确保讽刺有锚点、世界观自洽、与已有作品差异化。

## 适用场景

- 启动新的讽刺修仙项目时，快速生成世界观
- 切换题材（从经济焦虑切到职场/医疗/算法等）时复用流程
- 审查已有世界观的讽刺深度和一致性

## 核心流程（6 步）

### Step 1：痛点解构

输入一个现实痛点关键词，提取 5-8 个核心矛盾：

```
痛点: [关键词]
核心矛盾:
1. [个体 vs 系统] — 描述
2. [努力 vs 回报] — 描述
3. [真相 vs 表象] — 描述
4. [自由 vs 依赖] — 描述
5. [公平 vs 特权] — 描述
...
```

### Step 2：修仙概念映射

用映射表模板，将每个修仙核心概念对应到现实：

| 修仙概念 | 现实映射 | 讽刺锚点（读者会心一笑的场景） |
|----------|---------|---------------------------|
| 灵气/法力来源 | | |
| 修为境界划分 | | |
| 天道/规则 | | |
| 天劫 | | |
| 宗门 | | |
| 散修困境 | | |
| 闭关 | | |
| 法宝 | | |
| 丹药 | | |
| 飞升 | | |
| 心魔 | | |
| 道心 | | |
| 双修 | | |
| 渡劫 | | |
| 飞剑传书 | | |

**映射质量检查**：
- [ ] 每个映射都能让读者在 3 秒内 get 到现实对应
- [ ] 没有强行映射（如果某个概念映射不自然，可以跳过）
- [ ] 至少 10 个映射有明确的讽刺锚点

### Step 3：世界结构生成

按 4 个维度构建世界：

```markdown
## 经济系统
- 资源是什么？谁控制？怎么分配？
- 底层如何获取？代价是什么？

## 权力结构
- 谁在顶层？凭什么？
- 中间层的角色？
- 底层的出路（或没有出路）？

## 修炼机制
- 怎么修炼？需要什么条件？
- 天赋 vs 资源 vs 运气的权重？
- 有没有「捷径」？代价是什么？

## 社会分层
- 几个阶层？流动性如何？
- 阶层标志是什么（外在可见的）？
- 跨阶层互动的规则？
```

### Step 4：主角原型选择

从 3 个经典原型中选择：

| 原型 | 优势 | 风险 |
|------|------|------|
| **底层逆袭** | 代入感强，爽点明确 | 容易落入俗套 |
| **跌落重生** | 自带信息差，可以吐槽系统 | 需要解释为什么不直接碾压 |
| **系统内部人** | 视角独特，揭秘感强 | 主角动机需要额外设计 |

选择后填写：
```
原型: [选择]
名字: [谐音梗/暗示]
前世/背景: [一句话]
陨落/起点原因: [一句话]
核心矛盾: [知道规则 vs 不想再玩 / 想赢 vs 不想妥协 / ...]
金手指: [什么能力？限制是什么？]
```

### Step 5：讽刺锚点设计

每 10 章至少设计 1 个「读者会心一笑」的场景：

```
锚点 #N (约第 X 章):
  现实原型: [什么现实场景]
  修仙化表现: [在小说里怎么呈现]
  讽刺层次: [表面好笑 / 细想心酸 / 再想愤怒]
  角色反应: [主角/配角怎么反应，体现什么]
```

**锚点质量标准**：
- 不能是「作者跳出来解释讽刺」（meta_commentary = AI slop）
- 必须通过情节/对话/细节自然呈现
- 读者即使不 get 讽刺，也能当正常剧情看

### Step 6：差异化检查

与已有讽刺修仙作品对比：

| 维度 | 本作 | 《没钱修什么仙》 | 其他竞品 |
|------|------|----------------|---------|
| 痛点内核 | | 教育贷/阶层 | |
| 世界结构 | | 昆墟/宗门垄断 | |
| 主角类型 | | 穿越底层逆袭 | |
| 讽刺手法 | | 荒诞放大 | |
| 独特卖点 | | | |

**差异化通过标准**：
- [ ] 痛点内核与已有作品不重叠
- [ ] 世界结构有至少 2 个独创机制
- [ ] 主角动机/困境与已有作品本质不同

---

## 输出产物

完成 6 步后，输出 3 个文件：

1. **world.md** — 世界观完整设定（映射表 + 4 维结构 + 规则）
2. **characters.md** — 主角 + 核心配角设定
3. **satire-anchors.md** — 12+ 个讽刺锚点（对应 120 章）

这 3 个文件直接作为 Project Shell L1/L2 的输入。
